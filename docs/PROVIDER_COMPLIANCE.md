# Provider 合规决策记录

## 当前结论

状态：`UNVERIFIED`。

仓库实现不能替代合同或法律审查。高德开放平台条款对服务数据的下载、复制、缓存和
分离展示包含限制，因此在取得覆盖“由高德路线服务派生的 GPX/GeoJSON 文件导出”
的明确合同或书面授权前，生产环境默认关闭该能力。参考：
[高德开放平台服务协议](https://developer.amap.com/pages/terms/)。

默认策略仍允许：

- 在请求生命周期内把路线显示在找路页面；
- 生成到路线中点的高德 URI 交接；
- 保存不含路线几何的摘要，最长 24 小时。

默认策略不允许：

- 下载高德路线派生的 GPX；
- 下载高德路线派生的 GeoJSON；
- 长期保存高德路线几何。

## 地图图层扩展

`MapLayerProviderRegistry` 只提供技术解耦，不代表任意图层都可以与高德路线混合展示。
新增或替换卫星影像、地形、土地覆盖或其他参考图层前，必须单独确认：

1. 服务条款允许当前用途、地域、流量和终端展示；
2. 归属文字、Logo、审图号或其他展示要求已满足；
3. 坐标系与偏移处理正确，不会造成路线错位；
4. 该图层允许与当前路线 Provider 数据叠加；
5. 缓存、截图、导出和派生分析的权限边界已有记录。

注册项中的 `attribution` 与 `coordinateSystem` 是强制技术字段，但仍需由负责人保存
合同或数据许可证据。无法确认混合展示时，应切换完整 Provider profile，而不是只替换
底图 URL。

## 开启门禁

只有业务负责人确认授权证据覆盖供应商账号、应用 Key、数据类型、使用方式、地域和
有效期后，部署人员才能同时设置：

```text
AMAP_ROUTE_EXPORTS_ALLOWED=true
AMAP_ROUTE_EXPORT_AUTHORIZATION_REFERENCE=<可追溯的合同、工单或审批编号>
```

只设置开关而没有依据编号时，生产配置校验失败。依据编号最多 256 个字符，不会进入
公共 API、响应日志或指标。应用不会验证编号对应文件的真实性；证据本身应保存在组织
的合同或审批系统中，不应提交到 Git。

## 上线复核清单

1. 记录 Provider、账号、应用 Key 标识和授权主体；
2. 确认授权明确覆盖派生路线的用户下载与所需格式；
3. 记录地域、流量、有效期、署名和终止条款；
4. 由业务负责人和合规负责人共同批准，并保存审批编号；
5. 在预发布环境验证 API policy snapshot 与页面按钮；
6. 把授权到期日加入发布日历，并在续期前复核。

## 回滚

撤销、到期或无法确认授权时，把 `AMAP_ROUTE_EXPORTS_ALLOWED` 改回 `false` 并重新
部署。API 随即停止声明 GPX/GeoJSON 能力，页面自动隐藏下载按钮；高德 URI 交接与
`metadata-only` 策略保持不变。已产生文件的留存和删除按实际授权及组织政策另行处理。
